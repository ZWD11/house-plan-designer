# CAD 图纸怎么读（cadvec.py 用的规则 + 人工核对清单）

依据：《房屋建筑制图统一标准》GB/T 50001、《建筑制图标准》GB/T 50104（2010 版），以及装修公司原始结构图 / 拆改图的行业惯例。
**惯例在各家设计院、装修公司之间并不统一，图上有图例（凡例）就以图例为准。**

## 先分清是哪种图

| 图 | 特征 | 用什么 |
|---|---|---|
| CAD 导出的矢量 PDF | 放大不糊、能选中线条；`fitz` 读得到 `get_drawings()` | `cadvec.py`（精确到 mm） |
| DXF | AutoCAD / 天正 / 浩辰“另存为 DXF” | `cadvec.py`（自带单位，不用比例） |
| DWG | 二进制，读不了 | 让用户另存为 DXF（或用 ODA File Converter 转），或打印成 PDF |
| 扫描件 / 截图 / 只有位图的 PDF | 放大有像素 | 渲染成图片后用 `analyze.py`（黑底截图自动反相） |
| 开发商 / 贝壳户型图 | 彩色、带家具 | `analyze.py` |

判断 PDF：`python -c "import fitz;p=fitz.open('x.pdf')[0];print(len(p.get_drawings()), len(p.get_images()))"`，图元几千上万个 = 矢量。

## 图例 → 识别规则

| 画法（国标 / 惯例） | 含义 | cadvec 的处理 |
|---|---|---|
| 被剖切的墙、柱用**粗实线**轮廓；钢筋混凝土（剪力墙、柱）**涂黑** | 承重 / 结构 | 实心填充 → `solid`，厚 ≥ `--bearing-min`（默认 180）记 `bearing` |
| 灰色实心填充 | 非承重原墙（部分图把砌体墙填灰） | `grey` → 非承重 |
| **砖纹 / 斜线 / 网格**填充（PDF 里是一片细短线；DXF 是 ANSI31、AR-BRSTD 等图案 HATCH） | 装修图：**新砌墙**；建筑施工图：砌体填充墙 | `hatch` → `status: new`（`--hatch-as existing` 改成原墙） |
| 两条粗实线中间留白 | 轻质隔墙 / 砌体墙 | `outline` → 非承重原墙 |
| 虚线墙 / 黄色（或红色）墙 | 拆改图：拆除墙 | 不当墙（交给人确认，用设计器“拆墙”标记） |
| 墙线上 **3~4 条平行细线**（两条墙面线 + 1~2 条玻璃线） | 窗 | `window`；中间两条错开各占一半 = `slideWindow` |
| 窗外再凸出一圈平行线 | 飘窗 | 提示“可能是飘窗”，人工确认后改 `bay` |
| 门：门扇线 + **90° / 60° / 45° 开启弧线** | 平开门 | 弧心 = 门轴（`hinge`），弧在哪侧就往哪侧开（`into`）；两段弧 = 双开（半径不等 = 子母门） |
| 两条错开的门扇线 | 推拉门 | `sliding` |
| 断口里一条沿墙中线的单线 | 关闭画法的门扇（多见于入户门） | `door`，开向待定 |
| 断口里什么都没有 | 门洞（原始结构图） | `hole`；装修方案里卧室、卫生间一般要装门 |
| 断口里画了彩色框（黄 / 红） | 拆改图里的**新开洞口** | `door`，宽度取框的范围 |
| 方框 + 对角线（⊠ 或单斜线） | 烟道 / 风道 / 管井 | `shaft`；在厨房的改成 `flue` |
| 圆 + 十字（⊕） | 地漏 | `drain` |
| 单个小圆（直径 100~180） | 排水立管 / 下水口 | `sewer`，按位置确认 |
| 实心方块（不是墙的一段） | 柱、结构墩 | `column`（w、d 照量） |
| 墙外直线上的 **45° 短斜杠**（起止符号） | 尺寸线；斜杠 = 刻度 | `dims`；有文字层时自动读出数字核对比例 |
| 外墙外侧**三道尺寸** | 最外道 = 外包总尺寸；中间 = 轴线尺寸（开间、进深）；最里 = 门窗洞口、墙垛分段 | 总尺寸给 `--total-width`；分段用来对数 |
| **单点长画线** + 端部圆圈编号 | 定位轴线（墙、柱的中线或偏心线） | `axes`（轴线不一定是墙中线：外墙常偏心 120/250） |
| 文字层：卧室、客厅…… | 房间名 | 自动生成房间标签 |
| `M0921`、`FM1021`、`TLM`、`C1515`、`GC` | 门 / 防火门 / 推拉门 / 窗 / 高窗编号，后四位 = 宽高（分米） | 写到洞口的 `code`，用来核对洞宽 |
| “离地 900”“H:1300” | 窗台高、窗高 | 写进 `sill`、`head` |
| 一个铺满页面的深色底 | 黑底出图（模型空间配色） | 自动反相：浅色填充才是墙 |

## cadvec 的流程（出问题时知道看哪）

1. 读图元：填充多边形（同一路径里的多个圈按奇偶规则，带洞的字框不会变实心）、描边折线、圆弧（PDF 里是折线 / 贝塞尔，按“到圆心等距”拟合）、文字、DXF 标注 / 图块。
2. 实心填充做“坐标压缩”，按格子拆成水平 / 竖直墙段，横截面变化处断开（墙垛、L 形）——**这一步没有像素误差**。
3. 找尺寸线（直线 + 落在线上的 45° 斜杠），尺寸线和尺寸界线不参与找墙；只在实心墙外扩 2 个墙厚的范围里找墙。
4. 平行线配对成墙带：带里是细短线 = 填充墙（按有没有填充线切出门洞，洞口边吸到洞口边线上）；带里还有平行线 = 窗；空的 = 描边墙。窗必须落在墙线上（或在外墙上、两头接墙），描边墙的两条边线要首尾对齐——家具、洁具、柜子的轮廓就这样排除掉。
5. 同一直线（中线一致或一侧墙面齐平）的墙段串成墙线；并排的两层（砖内衬 + 混凝土）合成一面复合墙；段间断口按图元判断门窗；外墙凹口（两头都有垂直墙朝同一侧伸出、另一侧是室外）不是洞口。
6. 端点吸附到相交墙中线；被接上的墙没画到交点就延长；自由端正前方有垂直墙 = 靠墙角的门洞；转角差一点没接上的两面墙都延长到交点；错位的平行墙加一小段横墙接上；顶着结构块的墙穿过去。
7. 输出 HouseSpec 初稿（`draft.json`）和核对图（`cad.png`）。

## 尺寸：以标注数字为准

装修的人拿图纸上的数字对设计器，所以**有标注的地方，设计器里的墙厚、墙段、洞口、开间进深必须等于标注**。CAD 图上画的线和标注常差几毫米（量房图更常见：先量好数字再画图），不能按图形比例换算。
cadvec 按标注建立坐标：读出每段数字 → 每个方向做“刻度间距 = 标注值”的加权最小二乘（细部尺寸 > 轴线尺寸 > 总尺寸 > 室内尺寸）→ 墙面 / 洞口边吸到对应刻度（看尺寸界线伸到哪面墙）。
图纸自己矛盾的标注（分段之和 ≠ 总尺寸、两道尺寸量同一段数字不同）列在 `dim_conflicts`，按细部尺寸优先处理，交付时逐条告诉用户。

## 拿到 draft.json 之后人工核对

- **尺寸**：`cad.json` 的 `dims[].labels` 对照原图逐条看有没有读错（`?` 开头的是没读准的）；`labels` 和 `segs` 不等的地方要么在 `dim_conflicts` 里（图纸矛盾），要么是读错了——读错时在生成脚本里改墙，或者把那段标注值手工写进去重跑。
- **比例**：`scale_check` 里 `dims_read` / `width` / `dim_text` 应当一致；读不出标注时只能用 `--total-width`。外包总尺寸要量到“墙体外皮”（不含阳台栏板、空调板的话就不算进去）。
- **cad.png**：红框 = 实心墙，紫框 = 填充（新砌）墙，绿框 = 描边墙，蓝框 = 窗带；洞口框上写着类型。逐个看：
  - 门洞是不是被当成了窗 / 窗被当成了门洞（看 `openings[].why` 的判断依据）
  - 开放空间之间没有墙的地方（比如过厅和卧室之间只有一个 1100 的空当），设计器会把它们算成一个房间——这是图纸本身的样子，不要为了分房间凭空加墙
  - `free` 不为空的墙端：真的是墙垛 / 翼墙就留着，否则看是哪里没接上
- **承重**：图上没有图例时，“涂黑 = 承重”只是惯例。原始结构图里有的把所有原墙都涂黑（包括 120 的隔墙），所以 cadvec 只把 ≥180 的涂黑墙算承重；交付时要说明这一点，让用户以物业结构图为准。
- **门的开向**：原始结构图多半不画门扇，`draft.json` 里这些洞口是 `hole`；按房间功能决定装什么门、往哪开（卧室门一般内开、门轴靠墙角；卫生间门内开；入户门内开）。
- **房间名**：PDF 文字是 SHX 字体炸成的线条时读不出文字，房间名要看图补。


## 设计器导出的 DXF（src/export/dxf.ts）

按上面同一套国标习惯出图，打印到图框时：汉字 ≥ 3.5mm（房间名 5、面积 3.5、图名 7、比例 5）、尺寸数字 3mm；尺寸界线离开轮廓 2mm、超出尺寸线 2.5mm，起止符号 45° 长 2.5mm；
第一道尺寸离外轮廓 10mm、各道间距 8mm；定位轴线取承重墙（没有承重墙时取 ≥180 厚墙）和柱的中线，轴号圆直径 8mm，相距不到一个圆的不单设轴线；指北针圆直径 24mm、尾宽 3mm。
图层：WALL / WALL-HATCH / WALL-NEW / WALL-DEMO / COLUMN / DOOR / WINDOW / STRUCT / FURN / ELEC / ROOM-TEXT / AXIS / AXIS-NUM / DIM / ANNO / FRAME / TITLE。
骨架（图层、线型、文字样式）由 `scripts/dev/mk_dxf_template.py` 生成。cadvec 读 DXF 时跳过图框、标题栏、图名指北针图层。
尺寸：「国标」导出三道（门窗洞口 / 轴线 / 总尺寸；没有轴线时第二道退回墙厚 + 净距），「装修」导出四道（多一道墙厚 + 净距）。每段是 DIMENSION 对象（转角型，图形在 *Dn 块里，标注样式 GB，不写替代文字——CAD 显示的数就是两定义点的距离）。
门窗编号：M 平开 / 双开 / 子母 / 折叠门，TLM 推拉 / 隐形推拉门，DK 门洞，C 平开 / 推拉 / 落地窗，GC 高窗，TC 凸窗；后四位 = 洞口宽、高（分米，四舍五入）；
同号 = 同类型 + 同毫米尺寸 + 同窗台高，取整撞号的加 a、b、c；门窗表写毫米实数、数量、窗台高、入户门，以表为准。编号文字在 DOOR / WINDOW 图层（cadvec 能读回 code）。
图纸分两张：平面布置图（不含水电点位——不少看图软件不认“图层关闭”）和水电点位图（ELEC 图层打开，门窗表换成图例：符号 / 名称 / 数量 / 安装高度）。
房间名在房间里自动找不压家具、门窗编号、水电点位的位置；图名和比例按“不认宽度因子”的软件留间距。
对象组织：每段墙（墙线 + 填充）、每樘门窗、每根柱是一个编组（GROUP，AutoCAD 点一下选中整组）；每件家具是图块（INSERT，同款同参数共用块定义）。
墙不是天正那种“墙对象”（DXF 存不了天正自定义实体），拉一段墙不会带动相接的墙——要参数化改墙回设计器里改，再导出。
仍然没有的：门窗立面分格、材料说明（设计器里没有这些数据）。
