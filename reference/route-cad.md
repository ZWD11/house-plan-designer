# CAD 路线：矢量 PDF / DXF

### 2C. CAD 路线：矢量识别（PDF / DXF）

```bash
python scripts/cadvec.py 图纸.pdf --out <工作目录>/cad      # 图上有尺寸标注：自动读数字定比例、按标注定坐标
python scripts/cadvec.py 图纸.dxf --out <工作目录>/cad      # DXF：自带单位，标注图元（含改写的标注文字）直接用
python scripts/cadvec.py 图纸.pdf --total-width 10540 ...   # 读不出标注时才需要：最外道总尺寸（墙体外皮）
```

- **尺寸以标注数字为准（精度的关键）**：用户拿图纸上的数字逐个对设计器，**墙厚、每段墙、洞口、房间开间进深都必须等于标注**，不是“和图形差不多”。cadvec 的做法：
  1. 找全所有尺寸线（直线 + 落在线上的 45° 起止符号）和每个刻度的尺寸界线（界线另一头 = 被量的那个墙面）；
  2. 读出每段的数字：文字层直接读；没有文字层（SHX / TrueType 字体炸成轮廓，最常见）就用 `dimtext.py` 破译——同一张图同一个数字字形完全一样，按形状聚类，再用量出的长度投票“哪类字形是哪个数字”，挤在一起的两个数字（“390120”）会拆开分给相邻两段；读出的数字和图形差 > 12mm / 0.8% 的不用；
  3. 每个方向把所有标注当成“刻度之间的距离约束”做加权最小二乘：外侧分段最细的那道（门窗洞口细部尺寸）优先级最高，其次轴线尺寸、总尺寸，室内细部尺寸最低；明显读错的数字自动剔除；
  4. 墙面、洞口边离某个刻度 ~15mm 以内就直接取那个刻度的标注值（图上线和刻度常差几毫米），选哪个刻度先看它的尺寸界线是不是伸到了这面墙；
  5. 坐标精确到 0.5mm（245、225 这种奇数墙厚，中线在半毫米上，两侧墙面才是整数）。
- 输出里看：`scale_from` 写着“尺寸数字（n/m 段读出）”；`dim_labels` 读出比例；`dim_conflicts` 是**图纸自己前后矛盾**的标注（例如分段加起来 12070、总尺寸写 12060；两道尺寸量同一段一个 2770 一个 2775）——这些地方不可能同时满足，按“细部尺寸优先”处理，交付时要逐条告诉用户。
  `cad.json` 的 `dims[]`：每条尺寸线的 `labels`（读出的数字，`?xxx` = 没读准）和 `segs`（最终坐标量出来的长度），两者逐段相等才算对上；`cad.png` 上每段标注旁边写着读出的数字（绿 = 读出且一致，红 = 没读出）。
- 读不出数字（扫描件转的 PDF、字体特殊）时会退回整体比例：这时要加 `--total-width`，并在交付时说明尺寸是按图形量的、不是按标注。
- `cad.png`：毫米网格 + 墙段（红 = 实心承重、紫 = 填充新砌、绿 = 描边隔墙、蓝 = 窗带）+ 墙线 W 编号 + 洞口 O 编号和类型 + 符号 + 尺寸刻度，坐标直接就是 mm。
- `cad.json`：`openings[].why` 写着每个洞口的判断依据；`walls[].free` 是悬空端；`dims` 是尺寸线刻度（mm），可以和图上数字逐段对。
- `draft.json`：**基本可以直接用的 HouseSpec**——墙（含 `flush`、`status: new`、`bearing`）、门窗（有弧线的门带 `hinge` / `into`）、管井 / 地漏 / 柱、房间名（有文字层时）、底图。
  写生成脚本时**读入 draft.json 再补改**，不要重新手写墙：补房间名、把 `hole` 按房间功能换成门并定开向、窗台高、家具（见 `reference/cad-conventions.md` 末尾的核对清单）。
- 实测（本 skill 自带回归）：装修公司原始结构图 PDF，101 段标注读出 100 段，94 段与设计器尺寸差 ≤1mm，其余 6 段全是图纸自身矛盾；装修公司原始结构图 PDF，墙体与手工逐面量取一致（≤10mm），16 个洞口全部识别、类型正确；DXF（建筑 CAD 插件图层、门弧、图案填充、标注）往返 16/16、墙体 0 误差；黑底打印的 PDF 墙体全对。

### 兜底：cadvec 认不出墙（描边墙、只有颜色 / 线宽区分图层、数字炸成线条）

第二次实战（AH26110 别墅，6 页矢量 PDF，负二到顶层各一页）cadvec 报“没认出墙厚”、cadsplit 把一页切成两层。用 `cadpair.py`：

```bash
python scripts/cadpair.py 图纸.pdf --total-width 14025 --out <工作目录>/pair --names 负二层,负一层,一层,二层,三层,顶层
python scripts/cadpair.py 图纸.pdf --scale 29.03 --origin-pt 172.3 103.2 --out ...      # 已知 mm/pt 和原点
```

- 先看 `layers.json`：每类图元（描边 / 填充、线色、线宽、填充色）有多少条——哪类是墙线一眼看出（AH26110：黑色描边 = 墙，灰色填充 = 家具和文字，灰色小实心块 = 柱）。默认取黑色描边，`--wall-color r,g,b` 改。
- 墙 = 平行墙线配对：每 25mm 横切一刀，间距 60~340mm 的线成组，2 条 = 实墙、3~4 条 = 窗 / 玻璃（输出成 `glassWall` 洞口，按图改成窗型）；端点吸到相交墙中线。
- 柱 = 灰 / 黑实心近似矩形块（120~1200mm），去重；`pair<i>.png` 上紫框。
- 每页一层（不会把一页切成两层）；各页图框位置一致时共用一个原点（`report.json` 的 `shared_origin`）。
- **数字读不出来**（SHX 字体炸成线条）：问用户要一个总尺寸（`--total-width`），比例写进报告，交付时说明“尺寸按总尺寸反算”。
- 家具的黑色线（沙发扶手、椅子）会配出几段假墙，柜子贴墙时玻璃也会误判——初稿出来后**必须跑 `wallaudit.py` 全楼对账**（workflow-check.md），再逐张看 pair*.png。

### 结构与承重（写进 spec 的 bearing / bearingFrom）

- 图上**只有柱是实心填充、墙全是两线描边** = 框架结构：墙一律 `bearing: false`，只有地下室外墙按挡土承重墙。不要按“厚度 ≥ 200 就承重”（第二次实战全标错）。
- 涂黑 / 图例写明的承重墙写 `"bearingFrom": "drawing"`；按厚度、结构形式推断的写 `"bearingFrom": "inferred"`——属性栏显示「待确认」，承重的那些自动加一条批注；没写 `bearing` 的墙也按推断处理（标“待确认”，不加批注）。
- 用户问“承重怎么改”：顶部切到「原始结构」→ 选中墙 → 勾“承重墙”（拆改阶段选中墙时属性栏也有这句提示）。
