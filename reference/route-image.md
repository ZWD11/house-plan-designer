# 图片路线：户型图 / 截图 / 扫描件

适用：房产平台 / 家装设计平台户型图、售楼处户型图、手绘带尺寸的平面图、只有位图的 PDF（先用 `fitz` 200dpi 渲染成 PNG）。黑底 CAD 截图见文末「黑底 CAD 截图」。

### 1. 读图

查看户型图，记下：
- 最外圈总尺寸（总宽、总深 mm），以及分段尺寸
- 每个房间的名字和位置，门（开向、门轴在哪端）、窗、推拉门、入户门
- 门窗的具体类型：子母门、折叠门、隐形门；平开窗、推拉窗、落地窗、高窗、飘窗（判断方法见格式说明“门窗”一节）
- 承重墙（多数户型图用黑色/深色实心表示），柱、烟道、管井
- 指北针方向（写进 `north`）；用户提到城市就写进 `site`，日照模拟会按当地纬度算
- 图上标的面积，用来事后核对

图没有任何尺寸时，问用户要一个已知尺寸（比如某面墙多长），或者按常见尺寸估算，并且在交付时说明比例是估的。

### 2. 自动识别墙体（初稿 + 比例）

```bash
python scripts/analyze.py 户型图.jpg --total-width 12340 --total-height 11940 --out <工作目录>/analysis
```

- 输出 `mmPerPx`（比例），`scale_check` 里是按宽、按深分别算的比例。两者差 2% 以内说明比例可信。
  差得多通常是因为有凸出部分（飘窗、阳台）超出了总尺寸的范围：改用 `--dim 像素x0 像素x1 毫米`，按某一段标注线两端的像素位置定比例。
- `analysis.png`：原图 + 识别出的墙段（W 编号，红色 = 承重墙，橙色 = 非承重）+ 断口（G 编号，门窗候选）+ 尺寸线刻度（T/B/L/R 编号的紫色圈）+ 像素标尺，用来读坐标。
- **承重墙**：脚本按墙芯颜色自动分两类（深色 = 承重，`bearing_by: "color"`）。图上所有墙同一个颜色时只能按厚度猜（`bearing_by: "thickness"`），
  这些墙在 analysis.png 上编号带 `?`、也列在输出的 `bearing_unsure` 里——**必须对照原图图例逐面确认**（图例常写“承重墙 / 非承重墙 / 新建墙”）。
  常见画法：承重墙黑色或深灰实心、斜线填充；非承重墙浅灰实心或只画两条边线；外墙一般按承重处理；厨卫的 100~120mm 薄墙基本是非承重。
  颜色分界不对时用 `--bearing-max 亮度` 手动指定（承重墙颜色的最大亮度，0~255）。
- 隔墙只画了两条细边线、中间是白的（房产平台户型图常见）：加 `--outlined`，否则这些墙会漏掉。
- `analysis.json` 的 `dims_px`：每条尺寸线上的刻度（尺寸界线）像素位置，下一步精确定位墙要用。
- `draft.json`：直接可用的 HouseSpec 初稿（墙 + 门窗候选 + 底图参数）。**识别会漏墙**，漏掉的通常是：被窗户打断的墙段、很细的隔墙、浅色玻璃隔断；门窗类型也只是猜测。
- 墙体颜色偏浅、识别不到时调 `--gray-max 200`。图例、logo 被误识别成墙时用 `--crop x0 y0 x1 y1` 限定范围。

### 3. 写完整的 HouseSpec

（CAD 路线：读入 `cad/draft.json` 后只做补改，跳过下面第 1、2 条。）

推荐写一个小的 Python 生成脚本，不要手写 JSON。参考 `reference/example-gen.py`：用像素写墙，脚本统一换算成 mm。
1. **像素 → 毫米的换算（尺寸精度的关键）**：图上有分段尺寸标注时，一定用 `scripts/axismap.py` 按标注定位，不要只乘一个整体比例——
   户型图本身画得不准，整体按比例换算每面墙会差 20~80mm，标注数字才是准的。做法：
   - 在 `dims_px.top`（或 bottom）里挑一条分段尺寸线，按 analysis.png 上的刻度编号，把相邻刻度之间的标注数字读出来；
     刻度多出来的（文字、墙角误检）跳过，少的照原图补上像素位置。左 / 右侧同理得到竖直方向。
   - `X = Axis(chain(刻度像素, 各段毫米))`、`Y = Axis(chain(...))`，生成脚本里用 `X(px)`、`Y(px)` 代替 `(px-OX)*S`；`X.report()` 会标出读数可疑的段。
   - 看清标注量的是墙面还是轴线：量到墙面（净尺寸）时，墙中线 = 墙面 ± 墙厚 / 2。
   - 完整示例见 `reference/example-gen-precise.py`：两条尺寸线合成一个 `Axis`，墙写成 `(墙面像素1, 墙面像素2)` 时中线和墙厚都直接取标注；同一条墙线上黑色段、灰色段分开写（承重 / 非承重不同）。
   - 墙按标注修正后，靠墙家具会被设计器自动推出墙面（嵌入 ≤120mm 的），不用逐个改坐标。
   - 图上没有分段标注、只有总尺寸时，才退回整体比例：从 `analysis.json` 拿 `mmPerPx` 和外轮廓左上角像素 `outline_px[0..1]` 作为 S、OX、OY。
2. 对照 `analysis.png` 的像素标尺和 `segments_px`（每段墙的 line = 中线像素位置），逐面列出墙：外圈闭合，内墙端点落在别的墙中线上。
   墙厚按图上的像素厚度 × 比例取整（常见 240 / 200 / 120 / 100）。
3. 门窗：`from`/`to` 取洞口两端的像素。门要填 `into`（门开进去的那个房间里的一点）和 `hinge`。
4. 房间标签放在原图房间名的位置。
5. 承重 / 非承重按原图图例逐面核对（`bearing_unsure` 里的墙必须看）。
   同一直线上厚墙接薄墙（外墙段接隔墙、黑色段接灰色段）：设计器会按“没有垂直墙的那一侧平齐”自动处理；两侧都有 / 都没有垂直墙的交接点（外墙中段变薄、十字交叉）看原图哪一侧墙线连续，给薄墙手写 `flush`（格式说明“面齐平”）。交付前在 plan2d 截图里放大每个厚薄墙交接点确认没有错台。
6. **墙的位置和厚度按原图量墙面，不要按刻度猜**：`scripts/wallfit.py` 逐面墙量两个墙面（涂黑墙量黑块边、描边墙量两条线），给出中线和厚度。
   刻度常是轴线，墙不一定居中在轴线上（差 3~6px 就是几十毫米的错台）；外墙常比内墙厚（如 300 vs 200）；
   **描边画的非承重墙往往和同一直线上涂黑的承重墙一样厚、墙面对齐**，不要默认给 100。同一直线上厚度不同的两段，看原图哪一侧墙线连续，给薄的那段写 `flush`。
   check 会报「墙面错台」（房间里看得到的那一侧墙面没对齐），必须清零。
6. 再用标注尺寸核对一遍（下一步自查会把设计器算出来的尺寸列出来，逐个对数）。

### EXIF 方向

手机拍照 / 微信转发的图常带“旋转 90°”标记：看图软件里是竖的，PIL 直接读出来是横的。所有脚本读图都走 `scripts/imgio.py` 的 `open_upright`（先按 EXIF 摆正），build.py 打包底图也摆正，所以 analysis.png / gridmm / furnoverlay / 底图的像素坐标一致，不用再手工另存一张。
图上的字是倒着 / 侧着的（设计图整体转过）：underlay 写 `"rotate": 180`（顺时针度数），所有脚本和底图都会先转过来。

### 黑底 CAD 截图（模型空间截屏，没有矢量）

analyze.py 默认“深色 = 墙”，黑底图整张都是深色；按线色分图层 + 轴网定位：

```bash
python scripts/cadshot.py 截图.jpg --out <工作目录>/shot                                  # layers.png：各颜色分开，看哪个颜色是墙（建筑 CAD 插件默认青色）
python scripts/cadshot.py 截图.jpg --x-dims 3000 7200 3600 --y-dims <横轴之间的尺寸，从上到下> --out <工作目录>/shot
#   自动找轴号圆圈和轴线（axes.png 编号 X0.. / Y0..），按轴线之间的尺寸算 mm/px：shot.json 的 mmPerPx、x_fit / y_fit（每段比例、最大残差）、
#   axis_chain（生成脚本里 X = Axis(shot['axis_chain']['x'])，原点 = 第一根轴线）、dims_px（绿色尺寸线的刻度）
python scripts/analyze.py 截图.jpg --wall-color cyan --scale <mmPerPx> --out <工作目录>/analysis   # 墙 = 青色双线之间的窄带
```

- 线色约定（CAD 索引色）：青 = 墙 / 门窗、紫 = 洁具 / 家具 / 门窗编号、绿 = 尺寸线 / 轴号、黄 = 楼梯 / 填充、红 = 轴线、白 = 文字。JPEG 截图的细线发灰，cadshot 的饱和度门槛已经放低；建筑 CAD 插件的墙线常是偏绿的青（色相 75 左右）。
- 实测（第三次实战黑底截图 4096×4433）：4 根竖轴 + 8 根横轴自动找到，按 3000 / 7200 / 3600 定比例 5.902 mm/px，最大残差 0.9mm；`--wall-color cyan` 认出 37 段墙（窗洞处的墙线会被当成墙，门窗按图补）。
- 尺寸数字是位图：先用 `dimocr.py` 读（下一节），读不出的段人工读；尺寸链都填进 `dims`（见 workflow-check.md）让 check 逐刻度对账。

### 尺寸数字 OCR（位图兜底：dimocr.py）

```bash
python scripts/dimocr.py 图.jpg --scale <mmPerPx> --out <工作目录>/ocr                        # 白底户型图
python scripts/dimocr.py 黑底截图.jpg --color green --scale 5.902 --out <工作目录>/ocr        # 黑底：--color = 尺寸线颜色（数字是白的也行）
```

不装 OCR 库：同一张图里同一个数字字形几乎一样 → 字形聚类；按比例量出每段大概多长 → 投票定“哪类字形是哪个数字”（横向线先学，竖向线两个旋转方向都试，再合起来学一遍）→ 逐段读出，和量出的长度差 > 2% 的标 ✗。
- 输出 `ocr.json`（每条线每段的 `read`、`value`、`ok`）、`ocr.png`（读数标回图上，绿 = 对上、红 = 没对上）、`glyphs.png`（每类字形认成了哪个数字）。
- **只用 `ok` 的段**；✗ 的段看图人工补。比例要先有（cadshot / analyze / align2 算出来的），比例差 2% 以上会大面积 ✗。
- 实测：白底户型图四道外围尺寸链 22 段读对 19 段（读不出的 3 段都是“600”这种窄段、数字写在刻度外面）；黑底截图底部轴线 3/3、右侧尺寸链 8 段读对 6 段。
