# 生成与自查（build.py + check.mjs 循环）

### 4. 生成并自查（循环直到通过）

```bash
python scripts/build.py <工作目录>/spec.json -o <工作目录>/check.html
node scripts/check.mjs <工作目录>/check.html <工作目录>/check
```

`report.json` 逐项看：
- `freeWallEnds` 应为空（悬空的墙端 = 墙没接上，房间会漏成一片）。确实有半截墙（比如玄关隔断）时可以保留。
- `rooms`：每个房间都识别出来了，名字对，面积和原图标注接近（这里是净面积，一般比原图标的小一点）。出现“（未命名）”说明漏了标签，或者有墙没连上。
- `wallsDropped` 必须为空：spec 里写了、方案里却没有的墙（两面平行墙只差十几毫米时会被吸附吞掉——让它们落在同一条线上）。
- `wallsSkewed` 必须为空：原本横平竖直的墙，端点被吸附到旁边十几毫米外的另一个端点上，变成了斜墙（上面的门可能跟着歪掉 / 不画，开关会落到门洞里）。把相接的两段墙放到同一条中线上。`openingsHidden` 必须为空：方案里有、墙上却没画出来的门窗。
- `labelsOutsideRooms`、`openingsDropped` 应为空或 0（门窗放不下会被丢掉：洞口比墙段还长）。
- **尺寸逐个对数**：`exteriorDims` 是设计器按墙算出来的外围三道尺寸（`openings` 门窗分段、`axis` 墙厚 + 净距、`total` 总长），
  `rooms[].size_mm` 是矩形房间的开间 × 进深。和原图标注逐个比，**差 30mm 以上就回去改对应的墙**（多半是刻度读错、墙厚取错、或该用墙面却用了中线）。
  房间面积现在是按墙面精确算的净面积，和原图标的面积通常差 1% 以内（原图有的按轴线算，会偏大一点）。
- `errors` 必须为空。

**一定要看截图**：`overlay.png` 是生成的户型叠在原图上（半透明），墙、门窗位置应当和原图重合。`plan2d.png` 看门的开向，`view3d.png` 看整体。

### 尺寸链对账（dims / expectDims）——不只看外圈

spec 里把图上**每一道**尺寸链写进去，check.mjs 逐刻度对（每个刻度找模型里最近的墙中线 / 墙面 / 门窗洞口边 / 墙端，差 > 30mm 报出来）：

```jsonc
"dims": [
  {"name": "底部分段", "line": "y=11640", "at": [11640, 12250], "from": 0, "segs": [600, 1600, 800, 900, 1800, 1500, 2100, 900, 800, 2300, 500, 100]},
  {"name": "底部轴线", "line": "y=11640", "at": [11640, 12250], "from": 0, "segs": [3000, 7200, 3600], "ref": "center"},
  {"name": "强弱电井", "line": "y=8400", "from": -450, "segs": [450, 1450, 900, 650]},
  {"name": "右侧外道", "line": "x=13800", "at": [13800, 2900], "from": 0, "segs": [400, 1750, 1200, 2000, 2700, 4200, 1500, 1800], "tol": 30}
],
"expectDims": {"left": [240, 3260, 120, 2480, 240, 1780, 230, 4570, 240]}
```

- `line: 'y=…'` = 水平尺寸链（量 x），`'x=…'` = 竖直尺寸链（量 y）；`at` = 在哪几条扫描线上找墙（默认就是 line 那条，扫描线要穿过被量的墙）；`from` = 第一个刻度的坐标。
- `ref`：这道链量的是什么——`"center"` 轴线 / 墙中线（**轴线尺寸一定写**，不然旁边的墙面会顶替中线，墙挪了 100 多也查不出）、`"face"` 墙面 / 洞口边 / 墙端（门窗分段、净距），不写 = 都算。
- `expectDims` 按外围三道尺寸（`exteriorDims` 的“墙厚 + 净距”或“门窗分段”，自动取对得上的那道）逐段比，段数对不上直接报“漏墙或多墙”。
- 报告：`report.json` 的 `dimChains`（每个刻度的最近特征和差值）、`dimIssues`（超差的，要清零）、`dimConflicts`（**图纸自己前后矛盾**：两道链量同一处差 1~60mm，例如 C1518 窗宽 1500、尺寸链却是 1600）——矛盾的交付时逐条告诉用户按哪个建的。
- 自测（第三次实战户型）：把客厅 / 主卧之间那条轴线上的墙整体挪 120mm，「底部轴线」（`ref: center`）报“模型最近的是墙中线 10320，差 120mm（这一段标注 7200）”；书桌挪到窗帘前报「窗帘活动区」。

### 全楼墙体对账（wallaudit.py）

```bash
python scripts/wallaudit.py <工作目录>/spec.json --out <工作目录>/audit                     # 用每层 underlay 底图
python scripts/wallaudit.py <工作目录>/spec.json --pdf 图纸.pdf --scale 29.03 --origin-pt 172.3 103.2 --out ...   # 矢量 PDF 高清渲染再数
```

沿每段墙每 150mm 横切原图，数墙厚范围内几条线：2 条 = 实墙、3~4 条 = 窗 / 玻璃、没有 = 洞口 / 开敞、灰色填充 = 柱，和建模比对，只报不一致的，每处一张放大图（`sheet_<层>.png`）。墙边的衣柜、床头板、浴室柜先用 spec 的家具外框遮掉，不会被数成玻璃。
实测：AH26110 把二层的窗、落地玻璃全写成实墙（7 面墙、9 个洞口），8 处全部报出（图上=glass 建模=wall）。

### 反向对账：原图上有、模型里没有（coverage.py）

```bash
python scripts/coverage.py <工作目录>/spec.json --out <工作目录>/coverage
```

`wallaudit` 沿“已经建了的墙”去数线，漏建的墙它看不到；check 的悬空墙端也查不出“两头都接上了、整段没建”的墙。coverage 反过来查：
- **一致度**：原图墙像素被模型墙 / 柱覆盖的比例（自动判断实心墙 / 描边墙 / 黑底 CAD 截图）。
- **漏墙 M0…**：原图有墙、模型没有的块（≥ 300mm），每处一张放大图（`sheet_*.png`）。
- **墙面偏位 W…**：每面墙每 100mm 横切原图量两个墙面，中线差 > 30mm 或墙厚差 > 40mm 的列出（中位数）。底图整体偏了几十毫米会先估出来扣掉，并提示改 underlay 的 x / y。
- 一致度低于 95% 会先自动配准：底图比例 / 原点不对时直接给出改好的 underlay（和对齐后的一致度）——先对齐底图（或用 `rectify.py` 拉正）再看逐项。
- 家具外框、门扇扫过的范围、spec 的 `exclude` 区域、模型外 1.5m 以外不算。
- **门槛**：实心墙图一致度 ≥ 98%、漏墙 0、偏位 0。描边墙 / 黑底截图里家具双线框、文字会混进来，一致度做不到 98% 时**逐个看漏墙列表**：真漏的补墙，家具 / 符号写进交付说明。
- 实测（11 个已交付户型）：户型图3 阳台窗边两个墙垛没建（M0、M1 各 520mm）；户型图2 主卫墙位置差一个墙厚；大平层核心筒没建（按约定不还原 → 写 exclude）；“阳台入次卧”底图比例错了 30%，自动配准后给出正确 underlay。

### 门的开向（doorcheck.py）

```bash
python scripts/doorcheck.py <工作目录>/spec.json --out <工作目录>/doors                       # 只报不一致的
python scripts/doorcheck.py <工作目录>/spec.json --out … --write <工作目录>/spec_doors.json     # 有把握的直接改好另存
```

每扇平开门试 4 种画法（门轴在 from / to × 开向墙哪一侧），沿理论门弧 + 门扇线采样原图（深色线、浅色 / 虚线、彩色图木地板上的白线都认），
彩色户型图“不画线、画一块浅色扇形”的门按扇形内外反差认；相邻门的扇形互相不借分。和 spec 的 hinge / into 不一样就报，`doors_*.png` 里绿 = spec、红 = 原图。
- 自测：四室两卫 8 扇门全部翻转门轴 → 8/8 报出；全部翻转开向 → 8/8 报出；`--write` 改回后复查 0 处。彩色户型图翻转门轴 6 扇报出 4 扇（另 2 扇在花纹地砖的卫生间里，原图门弧认不出，列在“认不出”里人工看）。
- 生成脚本写完门之后跑一次；**认不出的门**（得分低）人工放大原图看。

### 交付前固定跑五个对账

1. 墙体正向：`wallaudit.py`（全楼）；2. 墙体反向：`coverage.py`（漏墙、偏位、一致度）；3. 尺寸链：check.mjs 的 `dimIssues` / `dimConflicts`；
4. 门开向：`doorcheck.py`；5. 家具：`furnoverlay.py --floor i` 逐层叠图 + check 的摆放检查（下一节）。房间面积写了 `area` 的，check 的「面积对不上」也必须清零。
用户说“整栋重新检查”时跑全套，不要只修用户指的那一处（第二次实战先修点、用户再指下一处，来回了 4 轮）。结果和「待确认清单」一起交给用户。

### 摆放常识（设计器自查已内置，warn 必须清零）

- 「窗帘活动区」：窗帘前 150mm 内有高于 600 的落地家具（书桌贴窗帘、柜子 / 柜机空调顶着窗帘；床头柜这类矮的不算）。书桌对窗时离墙 ≥ 300。
- 「推拉门被挡」：推拉 / 折叠 / 隐形门洞前 400mm 内有家具（阳台高柜压住门洞西端、洗衣池挡在门前）。柜子收进门旁的墙垛。
- 「高柜挡窗」：高于窗台的柜子、书架、冰箱放在窗前 400mm 内。
- 「水电 … 被 xx 挡住」现在带家具 key 和点位坐标；`report.json` 的 `issuesDetail` 有每条的位置（at）和涉及的家具 / 门窗 id，不用再写脚本查 plan.elec。
- 栏板洞口（`hole` + `sill ≥ 900`）不参与通道检查；不写 `head` 时洞口默认开到层高（只砌栏板，不在上面补一截墙）。

### 其他工具

- `node scripts/closeup.mjs 设计器.html x y 方向 out.png [--floor i]`：站在 (x, y) 朝北 / 东 / 南 / 西 拍一张漫游近景（正式 HTML 的 `?debug` 暴露 `window.shot(x, y, yaw, pitch, t)`）。用户说“这个柜子不对”时先拍近景再改。
- `node scripts/clicktest.mjs 设计器.html x y [x y …]`：2D 里模拟点选，看点中的是什么（土层 / 大造型挡点选时用）。
- `node scripts/dev/eval.mjs URL "<async 函数体>"`：页面里执行脚本取方案数据。
- build.py 每次记录每层墙数，**比上次少会打 [warn]**：生成脚本里的注释吞掉了一面墙时能发现。生成脚本**一律不用行尾注释**（注释独占一行）：用脚本替换代码时把注释插进行中间，会把后半行代码注释掉。
